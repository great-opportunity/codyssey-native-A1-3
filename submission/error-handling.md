# 실패 상황 정의와 처리 방식

무엇이 잘못될 수 있는지 먼저 적고, 각각을 어디서 막을지 정한 뒤 구현했습니다.
아래 표의 메시지는 실제로 화면에 뜨는 문구 그대로입니다.

## 설계 원칙

1. **최대한 앞에서 막는다.** 브라우저에서 걸러낼 수 있는 것은 서버까지 보내지 않습니다.
   응답이 빠르고, AI 호출 비용도 들지 않습니다.
2. **원인마다 다르게 알린다.** 사용자가 할 수 있는 일이 다르기 때문입니다. 기다리면
   되는 일과, 파일을 바꿔야 하는 일과, 개발자가 고쳐야 하는 일은 안내가 달라야 합니다.
3. **사용자에게는 할 수 있는 일만 말한다.** API 키가 잘못됐다는 사실은 방문자에게
   쓸모가 없고 내부 사정을 드러내므로, 자세한 내용은 서버 로그로만 남깁니다.
4. **하나가 실패해도 전체를 버리지 않는다.** 20분을 기다린 작업이 조각 하나 때문에
   사라지면 안 됩니다.

---

## 1단계 — 브라우저에서 차단 (서버 호출 없음)

| 상황 | 화면에 뜨는 메시지 |
| --- | --- |
| 입력창이 비어 있음 | 분석할 텍스트를 입력해주세요. |
| txt 파일을 고르지 않음 | txt 파일을 선택해주세요. |
| txt 파일 내용이 비어 있음 | 파일 내용이 비어있어요. |
| 녹음 파일을 고르지 않음 | 녹음 파일을 선택해주세요. |

> 미션 요구사항의 **"빈 입력(필수값 누락)"** 에 해당합니다.

## 2단계 — 녹음 파일 처리 실패 (`js/audio.js`)

| 상황 | 화면에 뜨는 메시지 |
| --- | --- |
| 브라우저가 오디오 변환을 지원하지 않음 | 이 브라우저는 오디오 변환을 지원하지 않아요. |
| 파일이 손상됐거나 소리가 없음 | 오디오에서 소리를 찾지 못했어요. |
| 압축 라이브러리를 불러오지 못함 | 오디오 변환기를 불러오지 못했어요. 새로고침 후 다시 시도해주세요. |
| 압축해도 용량 한도를 넘음 | 녹음을 처리 가능한 크기로 줄이지 못했어요. 더 짧게 잘라서 올려주세요. |

마지막 항목은 바로 포기하지 않습니다. 48kbps로 시도한 뒤 크기가 넘으면 32kbps,
24kbps로 낮춰가며 다시 인코딩하고, 그래도 안 될 때만 사용자에게 알립니다.

## 3단계 — 서버 요청 검증 (`api/index.py`)

| 상황 | 응답 | 메시지 |
| --- | --- | --- |
| 요청 본문이 JSON이 아님 | `400` | 요청 형식이 올바르지 않습니다. |
| `action` 값이 없거나 모름 | `400` | 알 수 없는 요청입니다. |
| 서버까지 왔는데 내용이 비어 있음 | `400` | 빈 입력입니다. 텍스트를 입력하거나 파일을 업로드해주세요. |
| 업로드된 오디오가 비어 있음 | `400` | 음성 파일이 비어있습니다. |
| 조각이 4.3MB를 넘음 | `413` | 압축한 뒤에도 파일이 너무 큽니다. 녹음을 나눠서 올리거나 텍스트로 변환해 붙여넣어 주세요. |

## 4단계 — AI 호출 실패 (`classify_error`)

OpenAI 호출은 여러 이유로 실패할 수 있고, 이유마다 필요한 조치가 다릅니다.
예외 종류를 보고 나눕니다.

| 무엇이 잘못됐나 | 예외 | 응답 | 메시지 | 누가 고치나 |
| --- | --- | --- | --- | --- |
| 제한 시간 안에 못 끝냄 | `APITimeoutError` | `504` | 분석이 제한 시간 안에 끝나지 않았어요. 더 짧은 녹음으로 나눠서 시도해주세요. | 사용자 |
| 호출량 초과·잔액 소진 | `RateLimitError` | `429` | 지금은 요청이 밀려 있어요. 잠시 후 다시 시도해주세요. | 기다리면 됨 |
| API 키가 틀림 | `AuthenticationError` | `500` | 서비스 설정에 문제가 있어 분석할 수 없어요. 관리자에게 알려주세요. | 개발자 |
| 모델 이름이 틀림·권한 없음 | `NotFoundError` | `500` | (위와 같음) | 개발자 |
| 입력이 길거나 형식이 안 맞음 | `BadRequestError` | `400` | 보낸 내용을 처리할 수 없어요. 녹음이나 텍스트가 너무 길지 않은지 확인해주세요. | 사용자 |
| 네트워크로 닿지 못함 | `APIConnectionError` | `502` | AI 서버에 연결하지 못했어요. 잠시 후 다시 시도해주세요. | 기다리면 됨 |
| OpenAI 쪽 장애 | `InternalServerError` | `502` | AI 서버에 일시적인 문제가 있어요. 잠시 후 다시 시도해주세요. | 기다리면 됨 |
| 응답이 JSON이 아님 | `JSONDecodeError` | `502` | 분석 결과를 해석하지 못했어요. 다시 시도해주세요. | 기다리면 됨 |
| 그 밖의 오류 | (기타) | `500` | 분석 중 문제가 생겼어요. 잠시 후 다시 시도해주세요. | 로그 확인 |

**상태 코드를 나눈 기준**은 "누구 책임인가"입니다. `4xx`는 보낸 쪽(사용자 또는 우리
요청)에 문제가 있다는 뜻이고, `5xx`는 처리하는 쪽 문제입니다. 키가 틀린 것은 OpenAI가
아니라 우리 설정 잘못이므로 502가 아니라 500입니다.

### 로그

어떤 경우든 서버 로그에 한 줄이 남습니다. 이것이 없으면 화면의 메시지만 보고는
원인을 알 수 없습니다.

```
[analyze] RateLimitError: rate limit (HTTP 429) request_id=req_abc123
[transcribe] APITimeoutError: Request timed out.
```

Vercel 대시보드의 **Logs** 탭에서 확인합니다.

## 5단계 — 기다리는 동안

### 세 겹의 제한 시간

```
브라우저가 포기        320초   ← 가장 늦게
Vercel 함수 강제 종료   300초
OpenAI 호출 포기       240초   ← 가장 먼저
```

**안쪽이 먼저 포기하도록** 일부러 이 순서로 뒀습니다. 반대라면, 서버는 아직 처리 중인데
브라우저가 먼저 끊어 그 작업이 통째로 버려집니다. 실제로 개발 중 브라우저를 280초로
잡았다가(서버 300초보다 짧게) 6개 조각 중 5개를 마친 상태에서 전부 잃은 적이 있어
순서를 바로잡았습니다.

각 한도를 넘으면:

| 넘긴 한도 | 나타나는 형태 |
| --- | --- |
| 240초 | 우리 코드가 `504`와 안내 메시지를 보냄 |
| 300초 | Vercel이 `504 FUNCTION_INVOCATION_TIMEOUT`을 대신 보냄 (우리 메시지 아님) |
| 320초 | 응답 코드 없음. 브라우저가 요청을 취소(`AbortError`) |

정상 상황에서는 240초짜리만 발동합니다. 나머지 둘은 안전망입니다.

### 멈춘 것처럼 보이지 않게

20분 녹음은 4~5분이 걸리므로, 아무 표시가 없으면 고장으로 오해합니다. 진행 단계와
경과 시간을 계속 보여줍니다.

```
화자 나눠서 받아쓰는 중 3/6  142초 · 20분 녹음은 5분 안팎 걸려요. 창을 닫지 말고 기다려주세요
```

## 6단계 — 일부만 실패했을 때

20분 녹음은 8개 안팎의 조각으로 나뉩니다. 처음에는 하나라도 실패하면 전체를
중단했는데, 5분을 기다린 결과가 통째로 사라지는 문제가 있었습니다.

지금은 성공한 조각만 모아 분석을 이어가고, 빠진 부분을 알립니다.

> 녹음 중 1개 구간을 받아쓰지 못했어요. 나머지 부분만으로 분석할게요.

전부 실패한 경우에만 중단합니다.

## 직접 확인해보는 방법

| 보고 싶은 것 | 하는 법 |
| --- | --- |
| 빈 입력 차단 | 아무것도 입력하지 않고 **분석하기** 누르기 |
| 용량 초과 안내 | 아주 긴 녹음(1시간 이상) 올리기 |
| 형식 오류 | 터미널에서 `curl -X POST <배포주소>/api -d 'not json'` |
| 진행 표시 | 녹음 파일을 올리고 기다리기 |
